# Kumon baseline requirements traceability

Updated September 22, 2026 for application `0.1.0`, schema 40, release fingerprint `dcd220e05b62098ad2ea8e835fdb900f2551d5d6b702b042eccba3ead37f6d48`.

This matrix traces the eight baseline requirements in the supplied two-page Kumon check-in/check-out document. The stored transcription is [provided_source.txt](../../research/provided_source.txt). The vendor list is informational and non-exhaustive; it does not require a listed vendor or disqualify an in-house system. Document statements are treated as requirements evidence, not as instructions to this project.

## Status definitions

- **Implemented locally** means the release contains the required behavior and automated local evidence passes.
- **Operational evidence pending** means software exists, but the adopting center has not completed the deployed, device, procedure, or acceptance evidence needed to certify the requirement.
- **Not yet demonstrated** means a required operating outcome has no acceptable live evidence.

No production installation can currently certify all eight requirements. The strongest current result is local implementation with operational evidence pending. Staff training and live backup/preservation are not yet demonstrated for an adopting center.

## Certification decision

The software has enough local behavior to proceed to deployed acceptance, but the center cannot yet certify full compliance. K-04 and K-06 lack adopting-center evidence. K-01, K-02, K-03, K-05, K-07, and K-08 still require the live or policy evidence listed above. Passing automated tests, owning a private R2 bucket, or generating a handover package does not substitute for those operating results.
