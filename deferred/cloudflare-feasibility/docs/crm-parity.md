Role differences remain explicit. Cloudflare currently limits student/guardian changes to owners and managers. Front-desk staff can record attendance, view student details, manage inquiries and log communications. Instructors have the current presence view and schedules, but no student directory, communications, bulk history, import or management controls. Railway grants some broader access. Keep the current Cloudflare limits unless the owner selects a different policy; do not silently widen them to claim parity.

The application uses server-confirmed attendance. It does not store durable offline attendance writes. Physical iPad testing and an approved, rehearsed outage procedure are still required.

A September 22 route audit maps every current Railway endpoint to the Cloudflare release. Railway passes 48/48 local tests, TypeScript, and its production build; its live web and PostgreSQL services report online, and the public health endpoint returns PostgreSQL `ok`. Cloudflare replaces Railway password sessions with Cloudflare Access, splits the monolithic bootstrap into bounded endpoints, maps incidents and reviews, and adds staff, kiosk, guardian-authority, history, archive, backup, retention, and audit controls. A later read-only Railway Postgres count found zero students, visits, attendance events, guardians, inquiries, schedules, and imports. One non-demo center, one owner account, one session, and seven audit entries remain.
